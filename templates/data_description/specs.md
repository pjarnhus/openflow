### Specs
The Specs are the specifications of the next sprint of the project,
supplied by the user as a standard markdown file at `docs/specs.md`.
The Specs are returned verbatim in their raw markdown form:

```markdown
# System Requirements

## Purpose

[Clear statement of the system's primary goal.]

## User Personas

- [Persona 1]: [Needs, responsibilities, and goals.]
- [Persona 2]: [Needs, responsibilities, and goals.]

## Functional Requirements

- [Requirement 1]: [Detailed description from the user's perspective.]
- [Requirement 2]: [Detailed description from the user's perspective.]

## Non-functional Requirements

- [Requirement 1]: [Detailed description.]
- [Requirement 2]: [Detailed description.]

## Constraints

- [Constraint 1]: [Description.]
- [Constraint 2]: [Description.]

## Existing Workflows

[Description of how the system integrates with or replaces current processes.]

## Success Criteria

[How the user will measure success.]
```

If no specs have been written for the project, the user will write "No specs found".
